## 2. 冻结的功能集（v2）

- **正常时钟**：无未来目标时显示本地 `HH:MM:SS`；时间无效显示 `--:--:--`。
- **带日期多目标倒计时**：`YYYY-MM-DD` + `HH:MM:SS`，最多 12 个；启用目标按 UTC 时刻
  升序、同刻去重；过期跳过；到点显示 `00:00:00` 后自动切下一个；无未来目标回时钟。
- **严格绑定时钟**：每秒 `time(NULL)` 重新计算“目标 − 当前时钟”，校时/改时区立即反映。
- **时区分钟偏移**：`tzOffsetMinutes` -720..840，支持 +05:30、+05:45、+12:45；
  目标按当前时区的本地墙上时间解释；不自动处理夏令时。
- **显示规则**：
  - 时钟 `HH:MM:SS`，默认白色；
  - 倒计时 `<100h` 为 `HH:MM:SS`，默认绿色；
  - 倒计时 `>=100h` 为 `DdHH:MM:SS`（如 `4d04:02:02`），小号字；
  - 剩余 ≤ `warnSeconds` 常亮红色，不闪烁；
  - IP / NO WIFI 为 6 秒小字覆盖层。
- **校时与离线**：WiFi 链路建立后 SNTP；在线每 60 秒检查，成功对时间隔 6 小时；
  网页加载偏差 >2 秒自动对时，保存后再静默对时；对时后断网继续走时。
- **持久化**：配置原子写 `/data/multitimer.conf`；时钟每 300 秒写
  `StoragePreferences` 的 `clockState`；重启时无 RTC 则以最后保存时刻恢复，联网后 SNTP 校正。
- **不做**：正计时、响铃、闪烁、每日循环点、自动 DST、OTA、MQTT、鉴权。

时间方案的关键点：设备**没有 RTC、没有 tzdata**；系统时区固定 UTC。运行中只用系统
UTC 时钟 + 分钟偏移计算本地时间；目标存本地日期/墙上时间而不是 epoch。因此改时区会
改变目标对应的 UTC 时刻，这是设计语义，不是漂移。

## 6. 遗留风险与已知限制

1. **无 RTC**：重启且离线时只能恢复到最后保存的时刻（每 300 秒落盘一次），
   断电期间的时间无法得知；首次开机完全离线且无保存值时会显示 `--:--:--`。
   实测一次冷启动落后 43 秒，联网后 SNTP 校正。
2. **无 tzdata / 不自动 DST**：只支持分钟偏移 -720..840；跨夏令时需手动调整。
3. **没有每日循环**：v1 的旧 `points` 只迁移为迁移当天的一次性目标；之后不重复。
4. **最多 12 个目标**；重复时刻去重保留配置中靠前者；非法单项被丢弃。
5. **HTTP 无鉴权/无 TLS**：`:8080` 只应放可信局域网；WiFi 密码和配置为明文文件。
6. **复位键恢复官方会清空 `/data`**：WiFi 凭据、`multitimer.conf`、`clockState`
   全部丢失；`/data` 没有完整可刷回镜像。
7. **2038 问题**：平台 `time_t` 为 32 位；接口范围写到 2100-01-01，
   实际可用时间受 2038-01-19 限制，目标/对时不要超过 2038。
8. **`/tmp` 易失**：`/tmp` 部署重启后消失；固化后的版本更新必须重新刷 `/res`。
9. **SNTP 依赖 UDP 123**：被路由器封锁时只能靠网页对时；网页时间来自浏览器。
10. **没有 WiFi 扫描列表**：手机页只能手填 SSID/密码；切换网络后设备会短暂离线。
11. **没有 OTA/MQTT/远程升级/配置导入导出**；没有持久化日志。
12. **镜像 8 MiB 上限**：当前 `res.tmp` 741,376 字节，余量充足，但新增资源要重新量。
13. **版本基线**：stock `/res` 来自当前设备（官方 1.1.3）。设备 OTA/恢复过其它版本后
    必须重新 pull，不能复用旧基线。
14. **防砖回滚依赖 `sys.zkapp.state`**：`Main.cpp` 在 `onEasyUIInit` 设置 `running`；
    如果新 App 在这之前崩溃，系统可能触发防砖回滚。不要删除或延迟该设置。
15. **仍需目视/长稳确认**：LED 实际观感、24h+ 稳定性、长期离线漂移、
    U 盘/TF 卡首次配网、复位键恢复演练。

## 7. 恢复工作

```powershell
# 1) 重新构建（headless）
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build.ps1 `
  -Workspace build\v2-workspace -LogPath build\v2-build.log

# 2) 主机单测
powershell -NoProfile -ExecutionPolicy Bypass -File tests\run_tests.ps1

# 3) 重新生成内嵌网页（改 web-src 后）并自检
python .\native\MultiTimer\tools\build_web_asset.py
node .\native\MultiTimer\tools\check_web.js

# 4) 重新生成 /res 镜像
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\make-image.ps1 `
  -SoPath dist\lib\libzkgui.so `
  -MainFtu native\MultiTimer\ui\main.ftu `
  -OutDir dist

# 5) 固化 DryRun（只读预检）
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\flash-update.ps1 `
  -Image dist\update.img

# 6) 人工复核后真正刷写
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\flash-update.ps1 `
  -Image dist\update.img -Confirm

# 7) /tmp 开发调试（不固化）
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\deploy-tmp.ps1 `
  -DeviceIp 192.168.31.124

# 8) 只读检查
.\tools\platform-tools\adb.exe connect 192.168.31.124:5555
.\tools\platform-tools\adb.exe -s 192.168.31.124:5555 shell `
  "ls -l /tmp /res/lib/libzkgui.so /res/etc/EasyUI.cfg /data/multitimer.conf"
Invoke-WebRequest -UseBasicParsing http://192.168.31.124:8080/api/status |
  Select-Object -ExpandProperty Content
.\tools\platform-tools\adb.exe -s 192.168.31.124:5555 logcat -d -v time
```

回滚：按住 USB-C 旁复位键约 5 秒再上电，恢复官方固件并**清空 `/data`**。
`deploy-tmp.ps1 -Restore` 只删 `/tmp` 覆盖层，不能恢复已替换的 stock `/res`。
