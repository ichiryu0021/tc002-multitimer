## 3. 页面系统与渲染（52×16）

### 3.1 页面类型（5 类）

| `type` | 屏幕行为 | 无未来目标时 | 时间无效时 |
|---|---|---|---|
| `clock` | 本地 `HH:MM:SS`，scale 2，居中 | 同（不依赖目标） | `--:--:--`，`#404040`，scale 2 |
| `clock_countdown` | 上半 0..7px 时钟；下半 8..15px 倒计时；两半均 scale 1，基线 7/14；每行在 52px 内尽量用大字距（先 spacing=3，放不下再降/截断） | 有已过期目标 → 正计时；**完全没有有效目标** → 下半 `NO COUNTDOWN`（dim） | 上半 `--:--:--`，下半留空 |
| `countdown` | 有未来目标 → 倒计时（`<100h` scale 2、`>=100h` 小号）；目标到达后 → 正计时（`colors.countup`） | 完全没有有效目标 → `NO COUNTDOWN`（dim，基线 10） | `--:--:--`，scale 2 |
| `live` | 上下两行，每行一个直播间；行高 8px，基线 6/14，scale 1 | 不受时间影响，照常显示直播值 | 不受时间影响 |
| `datetime` | 时间 `HH:MM:SS` scale 2（baseline 10，字距 2→0 自适应）+ 日期 `YYYY-MM-DD` scale 1（baseline 15，dim） | 同（不依赖目标） | `--:--:--`（基线 10，dim），不显示日期 |

- **正计时定义**：`TimerEngine` 在“没有未来目标、但至少有一个已过期目标”时返回
  `STAGE_COUNTUP`；`elapsedSeconds = now - 最近过期目标 epoch`（取已启用、合法目标里
  最晚的一个）。到点当秒仍算倒计时（显示 `00:00:00`），下一秒进入正计时。
- **NO COUNTDOWN 定义**：没有任何有效目标（无目标/全部停用/全部非法）→
  `STAGE_CLOCK`；页面渲染把“无未来目标且无已过期目标”显示为 `NO COUNTDOWN`（dim）。
  `/api/status` 的 `mode` 仍为 `clock`（没有单独的 `nocountdown` mode）。
- 正计时格式化复用倒计时格式：`HH:MM:SS`，≥100 小时用 `DdHH:MM:SS`（按现有
  `formatCountdown` 的小号规则）；正计时颜色 `colors.countup` 默认 `#00BFFF`。
- **日期**：只由 `datetime` 页展示，格式 `YYYY-MM-DD`；时间统一 `HH:MM:SS`。
- **严格绑定时钟不变**：每帧只取一次 `time(NULL)`，`evaluate(now)` 与渲染共用同一个
  `now`；分屏上下两半、时钟与倒计时/正计时严格同秒，改时区/对时后立即重算。

### 3.2 直播页几何与内容

```text
y=0        空（1 行）
y=1..5     第 1 行（上行）：<label><gap><value>      基线 6，字形占 1..5 行
y=6..8     中间留白（3 行）
y=9..13    第 2 行（下行）：<label><gap><value>      基线 14，字形占 9..13 行
y=14..15   空（2 行）
```

- 文本区：x=1..51（左侧 1px、右侧顶到最后一列），共 51px；`<label>` 左对齐、
  `<value>` 右对齐，gap 2px→1px 收紧，label 最多截到 1 字符，数值永不截断。
- `label`：手动填 1..3 个 `[A-Z0-9._-]`（统一大写）；空则自动生成
  “平台字母 + 房间号尾 2 位”，如 `B25`。平台字母：B/D/K（H/Y/C 为扩展位）。
- `value`：≤6 字符；`0..9999` 直接显示；万/亿用 `w/y` 后缀；`status` 显示 `LIVE`/`OFF`；
  失败/未配置显示 `--`。
- 颜色：label 平台色 **B `#FF6699`、D `#FFFFFF`、K `#FF9900`**；value 固定白色；
  陈旧值/`--` 用 `colors.dim`。
- 每页 **2 个槽位**（`rooms[0]` 上行、`rooms[1]` 下行）；空槽/`enabled=false` 整行留黑，
  不轮询；整页没有已配置房间时居中显示 `NO LIVE`（dim）。
- 最多 12 页、每页 2 个直播间 → 缓存上限 24 条。

### 3.3 覆盖层与横幅优先级

| 优先级 | 内容 | 触发 | 时长 |
|---|---|---|---|
| 1（最高） | 覆盖层：**IP 全屏 scale2 滚动**（无前缀）/ `NO WIFI`（两行小字）/ AP SSID+密码两行 / `AP ...` / `AP OFF` / `AP ERR` / `HTTP ERR` | 中键单击、右键长按进 AP、WiFi 连上、服务错误 | IP/AP IP 12s；NO WIFI 6s；AP 进入 10s；AP OFF 4s；AP ERR/HTTP ERR 6s |
| 2 | 切页横幅：上行 `shortTitle`（空则类型短名），下行 `n/N`；基线 7/14，scale 1 | 旋钮/API 切页 | **1200ms** |
| 3 | 页面内容 | — | — |

- **IP 全屏显示**：单行文本用 scale 2 在整屏居中（基线 13）；宽度超过 52px 时
  水平滚动，速度 **60ms/像素**（约 16.7px/s），滚动周期 = 文本宽度 + 8px 间隙，
  首尾相接；`NO WIFI`（含空格）仍按两行小字居中。
- 覆盖层激活时抑制横幅；覆盖期间 `/api/status` 的 `overlay=true`；
  覆盖结束后恢复当前页内容。
- 横幅只在页面真正改变时出现；只有 1 个启用页时旋钮无动作、不出横幅。

## 4. 按键 / 当前页持久化

| 输入 | 行为 |
|---|---|
| 中键**单击**（按下沿） | 显示 IP：STA 已连接 → DHCP IP，全屏 scale2 滚动 12s；未连接 → `NO WIFI` 6s；AP 模式 → AP IP（未就绪显示 SSID）12s |
| **右键长按 3s** | 进入/退出 SoftAP 配网：进入成功 → LED 显示 SSID + 固定密码两行 10s；退出 → `AP OFF` 4s；失败 → `AP ERR` 6s |
| 旋钮顺时针（CW） | **下一页**（正向） |
| 旋钮逆时针（CCW） | **上一页**（反向） |
| 旋钮按键 | 当前页是 `live` 时**立即刷新直播**（异步，不阻塞 UI） |
| 左键 | v3 不分配 |

- 翻页跳过 `enabled=false` 页面，默认循环；旋钮事件 120ms 去重、旋钮按键 300ms 去重。
- **中键长按不再用于配网**；SoftAP 只能由右键长按进入/退出（无 HTTP 开关）。
- **当前页持久化**：`StoragePreferences["uiState"] = "id,index,epoch"`；
  页面稳定 ≥30s 且距上次写 ≥120s 才落盘；恢复优先级：
  最后停留页 > `defaultPageId` > 第一个启用页；`POST /api/page {"reset":true}` 清记忆。
- 渲染节拍 250ms；只有秒变化/切页/横幅/覆盖层/直播数据变化才 `sendLedData`，
  稳态约 1 帧/秒；IP 滚动期间按滚动位置重绘。

## 6. 直播数据链路

### 6.1 `live.source` 四种模式

| 模式 | 行为 | 适用 |
|---|---|---|
| `off`（默认） | 不请求；直播页显示 `--` / `NO LIVE` | 未配置或不需要直播 |
| `bridge` | 设备每 `refreshSec` 对**当前页**发 1 个明文 HTTP GET 到 `live.url`，按页批量取 2 个房间（B 站/抖音/快手都由 bridge 提供） | 无 B 站直连需求时的通用方式 |
| `hybrid` | **B 站设备 HTTPS 直连**（镜像携带 OpenSSL 1.1.1w）；抖音/快手走 bridge；B 站直连失败且配了 `url` 时回退 bridge（60 分钟退避） | **推荐**（B 站直连、抖音/快手走 bridge） |
| `push` | 设备不轮询；外部程序 `POST /api/live` 推送 | 已有自动化/自控刷新节奏 |

### 6.2 B 站设备直连（v3.2 起可用）

- **镜像携带 OpenSSL 1.1.1w**：`native/MultiTimer/res-extra/lib/` 的
  `libssl.so.1.1`（352,540 B）+ `libcrypto.so.1.1`（1,737,128 B）随镜像安装到 `/res/lib/`；
  说明与许可见 [`native/MultiTimer/third_party/openssl-armhf/README.md`](../native/MultiTimer/third_party/openssl-armhf/README.md)。
- `TlsClient` 按顺序尝试：`MT_TLS_LIB_DIR`（仅测试）→ `/res/lib/libcrypto.so.1.1` +
  `/res/lib/libssl.so.1.1` → 系统 `libcrypto/libssl.so.1.1`；用 `dlopen(RTLD_GLOBAL)`
  保证 libssl 绑定到先加载的 1.1.1w。系统 1.1.0i 的 TLS client method 被裁掉
  （`SSL_connect` 141640BF `no protocols available`），只作最后回退（实际不可用）。
- TLS 参数：强制 TLS 1.2、SNI、主机名校验、`/res/ui/cacert.pem`（145 张根证书）；
  密码套件显式列表（ECDHE/GCM/CHACHA20 + HIGH，禁用 aNULL/MD5/RC4）；
  HTTP/1.0 GET，读到 EOF；单请求超时用 `live.timeoutMs`。
- 端点：主 `GET https://api.live.bilibili.com/xlive/web-room/v1/index/getH5InfoByRoom?room_id=<id>`，
  失败回退 `GET .../room/v1/Room/get_info?room_id=<id>`（兜底无 `likes`）。
- 指标：`online`（**人气值**，非并发人数）、`likes`、`fans`、`status`（1=直播中/0=未开播）、
  `title`；`code != 0` 视为房间失败；`room` 只接受 1..20 位 ASCII 数字；
  原始响应上限 64 KB。
- **真机证据**：停止 bridge 后，B 站示例房间（测试用）仍 `state=ok`
  （HTTPS 直连取到数据）；`hybrid` 下抖音/快手仍走 bridge。
- 直连失败时：每 60 分钟重试一次；`live.url` 非空则同轮回退 bridge。

### 6.3 抖音 / 快手走 bridge

- bridge 主程序：[`tools/live-bridge/bridge.py`](../tools/live-bridge/bridge.py)，
  PC/NAS/树莓派，Python 3.9+，默认 `0.0.0.0:8081`；
  文档 [`LIVE-BRIDGE.md`](LIVE-BRIDGE.md)，实测 [`VERIFY-bridge.md`](VERIFY-bridge.md)。
- 设备请求（明文 HTTP/1.0，收完即断）：

  ```text
  GET {live.url}?rooms=douyin:7076284313080843019,kuaishou:3xwnf96yetb5ewm
  Host: ...
  Accept: application/json
  Connection: close
  ```

  当前页 2 个房间一次请求（`platform:room`，房间号无需 URL 编码）。
- 响应（≤4096 B）：

  ```json
  {"ok":true,"ts":1792668766,"rooms":[
    {"key":"douyin:7076284313080843019","platform":"douyin","room":"7076284313080843019",
     "ok":true,"online":0,"likes":1107004,"fans":5123119,"status":0,"title":"..."}
  ]}
  ```

- 语义（设备与 bridge 一致）：**数值 `0` 是有效值**（未开播就是 0）；
  `ok:false`、房间项缺失、指标字段不存在 → 该格 `--`（陈旧时显示旧值 dim）；
  平台不提供的指标直接省略，不用 0 顶替。
- bridge 承担抖音匿名 `ttwid`（仅内存、2h 过期、不落盘）/19 位 `room_id`、
  快手 Playwright（无浏览器返回 `kuaishou_requires_browser`）、B 站兜底；
  抖音限流熔断、响应 4 KB 上限、缓存/限频见 [`LIVE-BRIDGE.md`](LIVE-BRIDGE.md)。
- **bridge 只适合可信局域网**：无鉴权/无 TLS，设备只接受 `http://`。

### 6.4 刷新调度与缓存

- `LiveService` 单后台线程；只轮询**当前页** 2 个房间。
  `hybrid`：B 站逐房间 HTTPS 直连；抖音/快手合并为 1 个 bridge 请求。
  `bridge`：三平台合并为 1 个 bridge 请求。
- 间隔 `live.refreshSec`（默认 30s）；`live.timeoutMs` 同时用于 B 站直连与 bridge
  请求（默认 3000ms，bridge 侧默认 2.5s 必答）；同时只允许 1 个在途请求。
- 切页/旋钮按键/保存配置/WiFi 恢复 → 立即刷新（urgent），不等下一个周期。
- 缓存按 `(platform, room)` 去重、跨页共享，最多 **24 条**；不持久化。
- 状态：`empty`（未配置/未启用，留黑）、`wait`、`ok`、`stale`（阈值
  `max(3×refreshSec, 60s)`）、`error`。
- 网络 I/O 不持锁、不阻塞 UI；`source=off` 不启动任何请求。

## 7. HTTP API v3

监听 `0.0.0.0:8080`（每连接独立线程，无鉴权/无 TLS，仅可信局域网）；
启动时另试监听 `0.0.0.0:80` 做 302 到 `:8080`（失败只告警）。
请求头上限 2 KB、请求体上限 **16 KB**、收发超时 3s、最多 8 个并发连接。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/config` | GET 返回 `{ok,config,device,ui,live}`；POST 只收 v3，保存 + 热应用 |
| POST | `/api/page` | `{"id":"p1"}`/`{"index":1}` 切页（不写配置）；`{"reset":true}` 清 `uiState` |
| GET | `/api/live/status` | 直播数据源健康 + 全部已配置房间快照（≤24） |
| POST | `/api/live/refresh` | 触发异步刷新（`{"page":N}` 可省）；返回 `{ok,queued,page}` |
| POST | `/api/live` | `push` 模式写缓存（body 同 bridge 响应） |
| GET | `/api/status` | v2 字段 + `state.page{}` + `state.text2`/`banner`/`overlay` |
| GET/POST | `/api/wifi*`、`/api/time` | 保持 v2.1.2 行为 |
| GET | `/`、`/index.html` | 内嵌手机页（gzip） |
| OPTIONS | `*` | CORS 204 |

### 7.1 `GET /api/config`（v3）

```json
{
  "ok": true,
  "config": { "...v3 schema（colors 含 countup；pages[].type 可为 datetime）..." },
  "device": { "ip": "...", "ssid": "...", "wifi": true, "uptimeSec": 715,
              "timeUtc": 1792668766, "timeValid": true, "tzOffsetMinutes": 480,
              "localTime": "2026-10-22 21:49:20", "lastSyncUtc": 1792668700,
              "apMode": false, "apSsid": "TC002-Setup", "apIp": "",
              "page": {"id": "p1", "index": 1, "title": "时钟+倒计时",
                       "type": "clock_countdown", "count": 5} },
  "ui": {"pageId": "p1", "pageIndex": 1, "pageCount": 5,
         "pageTitle": "时钟+倒计时", "pageType": "clock_countdown"},
  "live": {"source": "hybrid", "refreshSec": 30, "reachable": true,
           "lastOkUtc": 1792668766, "error": ""}
}
```

- `config` 永远 v3（磁盘旧配置在读取时迁移）；`ui`/`live` 运行时只读，POST 不接受。
- `device.page` 与顶层 `ui` 同义（兼容字段）；设备信息里的 `ip` 是 DHCP 实际地址；
  `pageCount` 为用户实际页数（示例设备已含 datetime 页，故为 5）。
- **无配置/损坏时 `GET /api/config` 返回默认 v3（4 页）**，与运行时兜底一致。

### 7.2 `GET /api/status`（v3；NO COUNTDOWN / datetime）

无目标 countdown 页示例：

```json
{
  "ok": true,
  "state": {
    "mode": "clock", "text": "NO COUNTDOWN", "text2": "",
    "remainSeconds": 0, "targetUtc": 0, "targetLocal": "",
    "warning": false, "smallFont": false, "overlay": false, "banner": false,
    "page": {"id": "p2", "index": 2, "title": "倒计时", "type": "countdown", "count": 5}
  }
}
```

无目标分屏页示例（`text` 为时钟、`text2` 为 NO COUNTDOWN）：

```json
{"mode": "clock", "text": "22:01:27", "text2": "NO COUNTDOWN",
 "page": {"id": "p1", "type": "clock_countdown"}}
```

datetime 页示例：

```json
{"mode": "clock", "text": "22:01:27", "text2": "2026-10-22",
 "page": {"id": "p4", "index": 4, "title": "日期+时间", "type": "datetime", "count": 5}}
```

- `mode`：`clock` / `countdown` / `countup` / `invalid`（页面计时部分；无目标仍为 `clock`）；
- `text`：该页主文本；`text2`：分屏下半文本（倒计时/正计时/`NO COUNTDOWN`/日期）或
  live 页指标名；
- `overlay`：中键单击显示 IP/`NO WIFI` 期间为 `true`；
- `state.page`：`{id,index,title,type,count}`；`device.page` 为兼容别名；
- 正计时时 `targetUtc/targetLocal` 指向“最近的已过期目标”（没有单独 elapsed 字段，
  正计时秒数在 `text`/`text2` 里）。

### 7.3 `POST /api/page`

请求 `{"id":"p1"}` 或 `{"index":1}` → `{"ok":true,"index":1,"pageCount":5,"page":{...}}`；
`{"reset":true}` → `{"ok":true,"reset":true}`。未知 id/越界 → 400。
只切页、不写配置文件。

### 7.4 `GET /api/live/status`

```json
{
  "ok": true,
  "source": {"kind": "hybrid", "url": "http://192.168.31.66:8081/live",
             "reachable": true, "lastAttemptUtc": 1792668766,
             "lastOkUtc": 1792668766, "error": ""},
  "refreshSec": 30,
  "timeoutMs": 3000,
  "activePage": 1,
  "rooms": [
    {"page": 1, "slot": 0, "platform": "bilibili", "room": "6", "label": "B6",
     "state": "ok", "updatedUtc": 1792668766, "ageSec": 4,
     "metrics": {"online": 204644, "likes": 4044425, "fans": 16896342, "status": 1}}
  ]
}
```

- 覆盖全部已配置房间（≤24）；`state` 取值 `empty`/`wait`/`ok`/`stale`/`error`；
  指标字段缺失表示平台本次未提供。

### 7.5 `POST /api/live/refresh` 与 `POST /api/live`

- `/api/live/refresh`：只置 urgent + notify，返回 `{"ok":true,"queued":true,"page":N}`。
- `/api/live`（push）：body 同 bridge 响应，返回 `{"ok":true,"updated":N,"ts":...}`。
- 错误统一 `{"ok":false,"error":"..."}`；请求体 >16 KB → 413；规范化配置 >12 KB → 413。

- **倒计时目标**：≤12，日期 + `HH:MM:SS`；本地备注；上移/下移/删除/移除已过期。
- **页面**：页面列表（序号/标题/类型/默认/当前；↑↓/删除/新增/编辑；“设为此页”调

## 11. v3.3 遗留风险与已知限制

除 v2.1.2 已知限制（无 RTC、无 tzdata、2038、HTTP 无鉴权、复位清 `/data`、
板载内存约 35 MB 等，见 [`STATE-2026-10-22-v21.md`](STATE-2026-10-22-v21.md) §7）外：

1. **B 站直连依赖镜像自带的 OpenSSL 1.1.1w**：若 `/res/lib/libssl.so.1.1` /
   `libcrypto.so.1.1` 缺失/被替换，会回退到系统 1.1.0i（无 TLS client，直连不可用，
   只能走 bridge）。镜像升级时不要漏掉 `res-extra` 的 2 个文件。
2. **镜像体积**：payload 23.15%（1,941,504 B，8 MiB 分区）；仍在预算内，
   后续不要再随意加大库。
3. **OpenSSL 1.1.1w 已 EOL（2023-09）**：只作设备端 B 站直连用途；需关注安全公告，
   升级时保持文件名/SONAME、同步 `third_party/openssl-armhf/README.md`、镜像 hash 与文档。
4. **B 站直连长期稳定性**：接口/证书/设备时间异常都会失败；失败回退 bridge 且
   60 分钟退避（`url` 非空时）。抖音/快手仍依赖 bridge（明文 + 无鉴权，只可信局域网）。
5. **正计时/NO COUNTDOWN 语义**：正计时只从“最近一个已过期目标”累计；
   **所有目标都被停用/无有效目标**时显示 `NO COUNTDOWN`（`mode=clock`）；
   到点当秒仍显示 `00:00:00`，下一秒进入正计时/NO COUNTDOWN。
6. **`display.splitBottomWhenIdle` 已废弃**：旧网页/脚本仍可读写，但固件渲染忽略
   `blank`，无目标固定 `NO COUNTDOWN`；旧网页 UI 与部分设计文档仍可能提到它。
7. **datetime 页是手动新增**：新装默认 4 页不含 datetime；旧网页/脚本若只认 4 种
   type 需要同步更新（当前网页已支持 5 种）。
8. **QA 报告滞后**：`docs/QA-v3-*.md` 是 v3.0 基线；v3.2/v3.3 无独立 QA 报告。
9. **物理输入未由用户确认**：中键单击 IP、右键长按 SoftAP、旋钮手感均需现场确认；
   软件层已按新映射实现并可通过 `/api/status` 观察覆盖层。
10. **回滚**：复位键恢复官方固件会清空 `/data`；v3 配置不能回滚给 v2 固件使用；
    v3.3 配置与 v3.2/v3.0 兼容（datetime 页在旧固件中会被忽略/拒绝，回滚前备份）。
